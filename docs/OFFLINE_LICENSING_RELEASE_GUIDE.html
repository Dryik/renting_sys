ARAK Rental Desk Offline Licensing Release Guide

A step-by-step production checklist for license key generation, installer build, Windows PC validation, offline activation, machine-binding checks, read-only mode, and backup behavior.

Target: Windows desktop app Model: Offline license + 15-day trial Scope: Anti-casual-copying
Intended behavior: valid paid license gives full access, active 15-day trial gives full access, expired/missing/invalid license and trial files place the app in read-only mode. Read-only mode still allows login, viewing data, reports, print/export, backup export, license request export, and license import.
Important: this system is not strong DRM. Do not add online activation, remote revocation, cloud checks, extra hardware fingerprinting, or aggressive anti-tamper logic.

1. Prepare A Clean Release Workspace

  1. Use a clean release branch or a clean copy of the repo.
  2. Make sure no production private keys are inside the repo.
  3. Make sure no generated customer license files are inside the repo.
  4. Make sure no client business data, uploaded files, screenshots, or request files are inside the repo.
  5. Install dependencies and run the verification commands.
npm ci
npm run typecheck
npm run lint
npm test
npm run build
Expected result: all commands pass before you create an installer.

2. Generate The Real Production License Keypair

Generate the production signing keypair on your own secure machine. Do not generate it on a client PC. 

node scripts/generate-license-keypair.mjs `
  --out-dir C:\secure\arak-license-keys `
  --key-id arak-license-key-2026-01

Expected output files:

C:\secure\arak-license-keys\arak-license-key-2026-01.private.pem
C:\secure\arak-license-keys\arak-license-key-2026-01.public.pem
File Purpose Where It Belongs
arak-license-key-2026-01.private.pem Signs customer license files. Secure private ARAK licensing machine only.
arak-license-key-2026-01.public.pem Lets the app verify license files. Embedded in the app before building the installer.

3. Store The Private Key Outside The Repo And App Bundle

Keep the private key in a secure location such as:

C:\secure\arak-license-keys\arak-license-key-2026-01.private.pem

The private key must never be placed in:

  • the Git repo
  • electron\
  • src\
  • scripts\ as a generated key file
  • out\
  • release\
  • the installer
  • client machines
  • normal business backups
  • source maps
  • screenshots or public support tickets
Recommended: keep one encrypted backup of the private key on an external drive or in a trusted password manager vault. If the private key is lost, future licenses for that key ID cannot be issued.

4. Replace The Embedded Public Key With The Production Public Key

Open this file in the repo:

C:\prototypes\renting_sys\electron\licensing\public-keys.ts

Replace the existing public key with the content of:

C:\secure\arak-license-keys\arak-license-key-2026-01.public.pem

The file should look like this:

export const licensePublicKeys: Record<string, string> = {
  "arak-license-key-2026-01": `-----BEGIN PUBLIC KEY-----
PASTE_PRODUCTION_PUBLIC_KEY_HERE
-----END PUBLIC KEY-----`,
};
Do not paste the private key here. The app should embed only the public verification key.

5. Build A Clean Production Installer

Remove old build outputs before creating the installer:

Remove-Item -Recurse -Force out, release -ErrorAction SilentlyContinue

Run the full release build:

npm run typecheck
npm run lint
npm test
npm run build
npm run dist

Expected installer output folder:

C:\prototypes\renting_sys\release\

Scan Release Output

Run this before sending the installer to anyone:

Get-ChildItem -Recurse release,out | Where-Object {
  $_.Name -match '\.map$|private|secret|\.key$|\.p8$|\.p12$|\.pfx$'
}
Expected result: no private key, secret, or source-map files are found.

6. Install On Windows PC #1

  1. Install the generated setup file on Windows PC #1.
  2. Launch the app.
  3. Confirm the app opens normally.
  4. Confirm the first launch starts the local trial.
  5. Confirm write access is enabled during the trial.

The app data folder is usually under:

%APPDATA%\ARAK Rental Desk

Confirm these exist in app data:

trial.json
trial-issued.json
rental_app.db
uploads\
Expected result: trial.json and trial-issued.json are created outside SQLite and outside uploads\.

7. Confirm Trial Duration And Machine Binding

Open trial.json and confirm:

  • schemaVersion is present.
  • productId is arak-rental-windows.
  • machineCode is a hashed value, not raw Windows MachineGuid.
  • startedAt and expiresAt are 15 x 24 hours apart.
  • integrity is present.

Open trial-issued.json and confirm:

  • productId is arak-rental-windows.
  • machineCode matches the hashed machine code from trial.json.
  • markerId or marker identity matches the issued trial.
  • integrity is present.
Do not ask clients to send raw Windows MachineGuid values. The app should show and export only the hashed machine code.

8. Export License Request From PC #1

Inside the app, go to:

App License > Export License Request

Save the request file somewhere easy to find, for example:

C:\Users\Client\Desktop\arak_license_request_XXXX.json

The request should contain only:

{
  "productId": "arak-rental-windows",
  "appVersion": "...",
  "machineCode": "...",
  "requestedAt": "..."
}
Expected result: request contains hashed machineCode, not raw MachineGuid, and no unnecessary personal or customer data.

9. Generate A Valid License For PC #1

Move the request file to your secure licensing machine.

node scripts/generate-license.mjs `
  --request C:\path\to\arak_license_request_XXXX.json `
  --private-key C:\secure\arak-license-keys\arak-license-key-2026-01.private.pem `
  --key-id arak-license-key-2026-01 `
  --license-id LIC-001 `
  --customer "Customer Name" `
  --out C:\secure\issued-licenses\LIC-001.json

For an expiring license, add:

--expires-at 2027-05-24T00:00:00.000Z

For a permanent license, omit --expires-at.

10. Import License On PC #1 And Confirm Full Access

  1. Copy only the generated license file to PC #1.
  2. Open the app.
  3. Go to App License > Import License File.
  4. Select the license file.

Expected result:

  • license import succeeds
  • status changes to licensed
  • customer name is shown if licensed
  • license ID is shown if licensed
  • full write access is enabled
  • license survives app restart

Restart the app and confirm it still shows licensed.

11. Copy License And Trial Files From PC #1 To Windows PC #2

From PC #1 app data, copy these files:

license.json
trial.json
trial-issued.json

On PC #2:

  1. Install the same app.
  2. Launch once if needed, then close it.
  3. Open PC #2 app-data directory.
  4. Place the copied files into that directory.
  5. Launch the app again.

Expected result:

  • PC #2 rejects the copied paid license.
  • PC #2 rejects the copied trial files.
  • The app remains read-only or reports wrong-machine/invalid state.
  • The copied license does not unlock PC #2.
Passing this check confirms that license and trial files are bound to the hashed Windows MachineGuid.

12. Confirm Backup Export Works In Read-Only Mode

On a read-only PC or read-only state, open:

Backup > Create Backup

Expected result:

  • backup export is allowed
  • a ZIP file is created
  • the user can still protect and export their own business data

13. Confirm Backup Restore Is Blocked In Read-Only Mode

Still in read-only mode, attempt:

Backup > Restore Backup

Expected result:

  • restore is blocked
  • no database files are replaced
  • no uploaded files are replaced
  • the app shows a clear license/read-only error
Backup restore must be blocked by Electron main-process IPC enforcement. It is not enough for the React UI to hide or disable the button.

14. Confirm Normal Backup ZIP Excludes License Files

Open the generated backup ZIP.

Allowed top-level contents:

metadata.json
rental_app.db
uploads\...

These must not appear anywhere in the ZIP:

license.json
trial.json
trial-issued.json
*.private.pem
*.private.key
*.key
*.p8
*.p12
*.pfx
*.map

Also confirm nested upload paths do not include sensitive files like:

uploads/license.json
uploads/trial.json
uploads/trial-issued.json
uploads/client.private.pem
uploads/file.map
uploads/private-key/anything
uploads/license-key/anything
uploads/secret/anything
uploads/signing-key/anything

15. Confirm Installer Or Update Does Not Delete Existing License

On PC #1 with a valid imported license:

  1. Close the app.
  2. Install the same version or a newer test installer over it.
  3. Launch the app again.

Expected result:

  • existing license.json remains in app data
  • app still shows licensed
  • trial.json is not deleted
  • trial-issued.json is not deleted
  • rental_app.db remains intact
  • uploads\ remains intact

The installer should update application files only. It must not wipe user data in the app-data directory.

16. Recommended Final Verification Commands

Before client delivery, run:

npm run typecheck
npm run lint
npm test
npm run build

Then run a smoke startup with temporary app data:

$tempDir = Join-Path $env:TEMP ('rental-release-smoke-' + [guid]::NewGuid().ToString())
New-Item -ItemType Directory -Path $tempDir | Out-Null
$env:RENTAL_APP_SMOKE_TEST='1'
$env:RENTAL_APP_USER_DATA_DIR=$tempDir
npm run start
Get-ChildItem -Force -LiteralPath $tempDir
Remove-Item -LiteralPath $tempDir -Recurse -Force

Expected temporary app-data files:

uploads\
rental_app.db
trial.json
trial-issued.json

17. Final Acceptance Checklist

18. Private Support Records To Keep

For each client, keep a private support record with:

  • customer name
  • license ID
  • issue date
  • expiry date, if any
  • license request file
  • hashed machine code from the request
  • license file issued
  • reissue notes
  • installer version delivered
Do not keep production private keys together with client request files or issued licenses. The private key should remain isolated on the secure licensing machine.

End of guide.
